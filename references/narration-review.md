# 文案复核清单

用于画面标题、正文、要点、旁白及试听稿的合成前复核。先读取 [文案与旁白规范](narration.md)，再检查完整稿件与已有功能依据；不要仅凭某个词或标点判断文风。

## 工作范围

- 新稿或获准修改的稿件：找出具体问题，做最小有效修改，再复核受影响的句子与上下文。已表达清楚的内容保留。
- 只审稿：保持原稿，只列出“原句 → 问题类型与原因 → 修改方向”。没有问题时直接说明；不为凑清单挑错，不给 AI 概率或推断作者身份。
- 只配音、换角色或重渲染：沿用已确认稿，不借复核擅自改写。

## 检查项

每项判断通过或未通过；未通过时定位原句及依据。默认在工作过程中完成，用户要求审稿报告时再展示结果。

| 检查项 | 通过条件 |
| --- | --- |
| 事实与边界 | 没有新增无依据的能力、数字、例子、来源或观点；保留格式、版本、适用条件、限制和真实不确定性。 |
| 通用句与伪分析 | 没有可任意套用的空泛评价、假洞见或无依据的意义解读；必要的通用功能说明未被误删。 |
| 句式与措辞 | 没有反问、设问、自问自答、串场填充、宣传套话、过度口语或公文式堆词。 |
| 术语与动作 | 同一对象名称一致，不混淆不同组件；能说清具体动作与结果，不用抽象词掩盖信息不足。 |
| 改写尺度与朗读 | 原意、专业信息和作者提供的表达特点仍在；不把长句全部切碎，不强制相同段落结构；朗读连贯。 |
| 画面与字幕 | 正文按用途提炼信息，旁白保持完整句意；字幕对应实际旁白，没有装饰性标记，不无目的地重复旁白全文。 |
| 结尾 | 结束在具体结果或有依据的下一步；没有新增总结复述、金句、比喻或泛化表态。 |

没有依据时，不为让检查通过而补写数据。可删去不影响核心信息的无依据评价；缺失信息影响核心功能说明时，标明缺项并取得依据。已有确认稿按上方工作范围处理。

修复发现的问题后复核；检查通过且已有生成授权时继续配音，不新增审批步骤。复核报告、修改说明和来源注记不写入 `narration`、画面正文或字幕。这里的通过是编辑判断，不是自动化测试或实际听感验收。

## 对照样例

以下仅为编辑示例，不是对任意产品的事实描述。

| 原句 | 问题与处理 |
| --- | --- |
| 最值得关注的是：支持 SRT 字幕导出，体现了对创作体验的持续追求。 | 假重点与伪分析；已有导出依据时保留“支持 SRT 字幕导出。” |
| 工具已生成旁白。助手将完成字幕对齐。引擎随后导出视频。 | 先核对是否为同一对象。若是，统一名称；若确为不同组件，保留区分。 |
| 目前仅支持 16:9 横屏，默认导出 1080p 视频。 | 有依据的能力与限制，完整保留；不要泛化为“提供高质量导出”。 |
| 导出视频与字幕。让每一次表达都拥有无限可能。 | 空泛收尾；删除第二句，不另造一个口号。 |
