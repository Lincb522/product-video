# 从产品内容到镜头

适用于完整产品介绍、功能演示和更新报告。用户已确认的结构、稿件、时长与素材优先；短预告和单项教程不必强加完整功能总览。

## 先理解产品

先读项目说明、当前功能入口和相关实现，再检查实际界面。将每项介绍内容对应到可展示的页面、操作结果或实现依据。不要仅凭旧宣传稿、菜单名称、截图文字或仓库愿景推断功能已经可用。

要求“最新”时，记录实际采集的版本或提交、时间、主题和状态。区分实际运行窗口、原生视图测试宿主、网页录屏、静态截图与示例素材；测试宿主画面不能写成连续真实操作录屏。缺少事实的能力不要写入旁白。

对完整介绍，先让观众知道产品做什么、主要功能之间有什么关系，再按工作流程展开。总览中的功能数量由产品决定；一组过多就分组，不能固定套六项。每段详细介绍尽量完成一个闭环：入口或输入 → 操作 → 可见结果 → 必要说明。更新报告按基线区分新增、优化与修复，并在相关段落说明技术栈和实现方式。

## 内容决定版式

| 内容 | 优先画面 | 文案作用 |
| --- | --- | --- |
| 主要功能总览 | `editorial.overview`，先展示分组，再按旁白放大对应界面 | 给每项清楚的功能名称 |
| 总览转入详细介绍 | `portal` 或有明确视觉对应的 Shotcraft 转场 | 标明正在进入的功能 |
| 界面中的具体操作 | 完整截图、按目标聚焦、操作前后状态或真实录屏 | 解释动作与结果 |
| 必要背景、使用条件 | `side` 图文并排 | 补充画面无法直接表达的信息 |
| 两种主题、状态或版本 | `pair`、同视图遮罩对照、翻面 | 准确标注差异 |
| 同类页面或多步骤结果 | `fan`、`filmstrip`、卡片展开 | 概括页面关系 |
| 技术栈与实现 | 代码片段、结构图、真实界面变化与说明结合 | 解释模块如何共同完成用户功能 |
| 品牌开场或段落结束 | 短标题、Logo、适量三维或原库收尾 | 交代产品名称与下一步 |

每镜只强调一个重点。标题、短说明与字幕分工明确，不把旁白整段贴到画面，也不让截图缩得无法阅读。设备模型只在形态、空间或屏幕演示确有作用时使用；不要反复用同一个三维镜头填充时长。除非介绍对象就是设备，不在旁白报设备型号。

## 运动服务信息

在分镜中为运动写明用途：建立整体关系、进入细节、按顺序展开、强调变化、比较状态或转入新章节。连续镜头避免反复使用同一种淡入与缩放。丰富效果时应跨用途选择，例如总览重排、逐行入场、镜头回正、焦点转移、卡片翻面和遮罩对照，而非给同一截图不断换转场。

使用 [内容镜头](editorial.md) 绑定产品图片与文字；需要更特别的运动再从 [完整 Shotcraft 镜头库](shotcraft.md) 查对应源码。分栏与逐行效果的切片边界取自实际截图，不能沿用上游示例的行高和列宽。效果库齐全不意味着每支宣传片要把全部效果插一遍；效果目录或用户明确要求的展示片才逐项覆盖。

## 用旁白校准时间

先完成简洁、专业的稿件复核，再生成或复用配音。以真实音频时长和字幕时间戳安排展示时间，不能只按字数估时。标题出现、总览聚焦与操作结果应对应正在讲述的内容。`steps[].at` 按本章音频时长定位；`editorial.focus_at` 按当前镜头的完整时长定位，两者不是同一个基准。

操作顺序保持移动 → 停留 → 按下或拖动 → 展示真实结果 → 驻留。快速说明可以缩短静态停留，不能把结果提前到点击前。正文过长就拆镜头或改写，不靠无限缩小字号。

## 交付前检查

先查关键帧，再播放实际 MP4。覆盖动作中间状态、每次总览聚焦、章节衔接、对照标签、字幕与图文安全区；分别检查长镜头后半段和成片末尾。`review PROJECT` 从已验证 MP4 提取复核帧，不能把提取成功写成视觉或听感已经通过。

交付实际文件及其时长、规格。用户要视频文件时，网页播放器只能作为辅助入口。保留当前成片和可编辑项目，不把旧版本删除当作更新步骤。
